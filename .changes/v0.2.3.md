### Fixed

- `s3_copy_object` with `REPLACE` and `s3_create_multipart_upload` reject
  browser-executable content types in the shared S3 adapter. Unlike
  `s3_put_object`, copy still permits an omitted or empty `contentType`, which
  lets S3 reset it to the default type instead of retaining the source type.
  `COPY` continues to ignore a supplied content type. (#542)
- `s3_put_object` accepts an empty `content` string and stores a zero-byte
  object instead of answering "Either filePath or content must be provided."
  (#505)
- Ignore non-CSV objects when choosing the comparison snapshot for usage growth. (#571)
- Validate multipart copy source versions against their bucket and object key before copying. Versioned copies reject conflicting or malformed selectors; unversioned copy sources pass through unchanged. (#1927)
- Treat an empty `copySourceVersionId` as omitted for compatibility; embedded source versions are still validated; omit both version selectors to copy the current version. (#1927)
- Presigned uploads now bind the approved Content-Type header; results include `requiredHeaders` with the exact Content-Type the upload must send. (#1927)
- Stage save-to-path downloads before creating destination directories so transfer failures leave no new directories or partial files. Finalization errors preserve parent directories; a hard kill can leave a .part file while the final path remains unchanged.
- Local filesystem policy refusals for `s3_put_object` `filePath` and `s3_get_object` `saveToPath`, including a configured `B2_FILE_ROOT` that does not exist, now return `bad_request` (HTTP 400) instead of `internal_error` (HTTP 500). (#452)
- Concurrent first report reads now reuse one S3 client, preventing an overwritten client from leaking. (#559)
- Native B2 writes no longer replay after a 401 response, socket reset, or timeout; ambiguous outcomes return operation_status_unknown without SDK retries, while reads retain safe reauthorization retries. (#475)
- Reject malformed base64 and conflicting input sources in `s3_put_object`, and
read local uploads through EOF within the inline size limit. (#553)
- Preserve unexpected filesystem failures as server errors and reject local paths containing NUL bytes as bad_request. (#452)
- Return the biggest storage declines first when usage growth uses shrinking order with a limit. (#558)
- Anchor usage growth comparison windows to the latest available report snapshot. (#582)
- Allow files and directories whose names begin with two dots inside a local
filesystem sandbox while continuing to reject paths outside it. (Refs #582)
- Raise the HTTP and serverless MCP body cap to 2 MiB to allow 1 MiB inline uploads. (#582)
- Keep temporary S3 fallback clients alive until download bodies finish or are
closed, and release them during shutdown. (Refs #582)
- Preserve cancellation for batch version checks, contain HTTP auth hook failures, avoid retrying multipart aborts, and release retry listeners. (#587)
- Allow omitted upload content types, reject mismatched inline download lengths,
validate multipart completion bounds, and omit the no-op multipart ACL. (Refs #587)
- Avoid a sanitizer RangeError when a proxied array reports a length above the native array-length limit. Preserve intact redaction markers when configured secrets match their contents, while continuing to redact real secrets outside or across marker boundaries (#469).
- Preserve underlying socket error codes in ambiguous-write warnings and keep unavailable optional diagnostic metadata from masking the original write outcome.
- Preserve prototype-named metadata as sanitized own data without replacing object, array, or Error prototypes.
- Treat only owned destructive detector entries as registered tools, so prototype-named unknown tools do not produce invalid effects or throw.
- Isolate cached OAuth authorization metadata from mutations made by individual verifier callers.
- Preserve durable-secret ledger write failure recovery, bounded replay, and ownership cleanup when synchronization fails.
- Durable-credential failure messages no longer point operators to the critical log for the created key or account, which that log no longer records; they now say to find it by listing keys or accounts created at that time.

  `brace-expansion`, `proxy-addr`, `smol-toml`, `source-map-js`, and `sharp`

  `deploy/customer-hosted` lockfiles. `braces` and `node-forge` have no patched

  `qs` (GHSA-6pq8-jhm2-2vcw, fixed in 6.16.1) advisories via pnpm overrides in
  the root, `deploy/customer-hosted`, and `tools/mutation` workspaces, and
  retired the `node-forge` and stale `braces` audit exceptions. The dev-only
  `zod` 3.x exception remains until a patched 3.x or the upstream tooling
  moves. (#524)
- Keep configured secrets redacted across nested MCP output, logs, and Error fields when supplied as a one-shot iterable. Found while closing sanitizer mutation-testing gaps (#469).
- Restrict durable-secret post-create logs to fixed operation context and allowlisted recovery statuses, preventing provider results and callback-controlled details from exposing minted values.
